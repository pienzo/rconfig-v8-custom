## F02 design alternatives (proposal, not implemented)
**A — Preferred:** extend existing Task Wizard and scheduler with explicit `external-file` task subtype, job and guarded dispatch; use additive rule/check-run records linked to `Device`/`Task`. Constrain the server-controlled inbox to per-device IDs. Distinguish `PENDING`, `SUCCESS` and reasoned failure states; UTC event timestamps; regular readable nonempty stable files; strict basename glob/regex; no reuse of older files, no symlinks/traversal; deduplicate and make retries idempotent. **No SSH commands to devices, no automatic file import/deletion for MVP.** Proposed entity/job names are conceptual, not upstream classes.
**B — Alternative:** separate rules and scheduler. This simplifies isolation but duplicates native UI/scheduler/reporting; choose only if the native task model proves unsuitable in tests.
Check architecture and threat model before implementation; a successful file check verifies arrival/freshness, **not restorability**.
