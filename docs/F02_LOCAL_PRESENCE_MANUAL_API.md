# Local Presence — asynchronous Verify Now API

Pre-release contract. Authentication via existing internal API and Admin role. Not exposed through external API v1/v2. No approval to activate or deploy.

Base path: `/api/tasks/local-backup-presence-rules/{ruleId}/verify-now`.

| Method and suffix | Result |
| --- | --- |
| POST (no suffix) | 202, create or return the existing unexpired diagnostic (including terminal); idempotent |
| GET /{sessionId} | 200, exact UUID and rule, unexpired; read-only |
| POST /{sessionId}/restart | 202, replace only the explicitly selected unexpired terminal UUID; stale/queued/pending conflict |

No parameters accepted (empty body, empty JSON object/array; no query fields). The rule determines trusted criteria. UUID is generated by the service, never accepted as admission state. Invalid or missing session UUID on GET is 404, stale restart is 409. Admission/restart configuration or capacity conflicts and closed approval gates are sanitized 409 responses; malformed payload is 422; authentication/authorization uses existing 401/403. Write throttle shared across start/restart: 6 per minute; polling: 60 per minute, separate bucket. Responses with session data are private/no-store.

`data` contains id, rule_id, status, requested_at_utc, expires_at_utc, next_observation_at_utc, result (nullable, only reason, filename, observed_at_utc), evidence_type=metadata_presence, persistent_check_run=false, verified_success=false. Statuses queued, pending, present, absent, error. Only safe basename and recognized reason/status pairs are projected; no raw result, continuation, root mapping, inode, or queue cooldown. Present is metadata evidence, not proof of transfer completion or restorability. GET does not renew or prune TTL. Start after expiry can create a fresh UUID. Rule edits/activation invalidate sessions per existing lifecycle.

## Approval and operation

`manual_available` on the administrator rules list reflects static `manual_api_enabled` plus all existing manual reconciliation gates, not worker health, capacity, or mount readiness. New flag defaults false, no environment binding. Before changing it, follow [activation checklist](F02_LOCAL_PRESENCE_ACTIVATION.md), attest matching role configuration, read-only worker mount, isolated queue, scheduler heartbeat, capacity and timeout/retry ordering. Test only synthetic data. Never enable the flag solely because CI passes. HTTP only admits/polls DB state; scheduled reconciliation and worker handle file metadata. Closing the API gate refuses HTTP access including polling without cancelling existing sessions; drain/expire using the existing controlled operator procedure. No new schema or production changes.

## Acceptance

Controller tests cover auth, gates, input, idempotency, exact UUID scope, expiry, restart, capacity, sanitized projection and no dispatch/history/notification side effects. Hosted HTTP-to-worker integration and UI polling/expiry/restart remain separate acceptance gates. No deployment approval.
