# Local presence bound directory observation (#210)

Code-only foundation for #196, based on accepted #207 while #209 CI is pending. The new scanner method returns the existing bounded metadata scan and a versioned SHA-256 fingerprint of the checked absolute directory chain, device/inode/mode/uid/gid. This is an internal equality check, not a secret or authorization token. Do not expose it to clients. Ordinary file arrivals do not alter the fingerprint; a remapped alias or replaced directory normally does. Optional expected fingerprint is checked before enumeration, then the original in-scan identity checks are applied. Existing scanMapped return shape and strict numeric scanner remain compatible.

Metadata fingerprints are not atomic openat traversal or guaranteed unique identities across inode reuse, namespaces or mounts. Protected ancestors, read-only mounts and operator-controlled mappings remain mandatory. A worker/container restart may alter ancestor identity: fail closed rather than silently reuse prior observations. The next integration must persist the fingerprint and earlier metadata with the same occurrence/criteria and use a trusted clock, without exposing paths or file contents. No persistence, activation, queue, API or staging changes in this PR. Rollback: code-only revert.
