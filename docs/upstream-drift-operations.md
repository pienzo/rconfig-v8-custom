# Read-only upstream drift report (issue #149)

The baseline is Core `core-8.3.0` / `121cff1b243794af260f6c5850553b5f1b0af881`. The annotated tag was peeled to that commit. On 2026-11-24 upstream/main and fork/main were identical; custom contained the baseline. The report checks the latest stable Core tag and its resolved commit, the immutable recorded baseline tag, fork main drift, and custom ancestry. Local git ancestry counts from explicitly fetched public refs are evidence of ancestry, not a complete security or migration review. It reads the remote custom ref, not the candidate PR checkout, by design.

Run `python3 tools/upstream/drift.py` from a reviewed checkout of custom, with access to public GitHub API. Manual execution needs no token or secrets. Hosted CI uses its ephemeral contents:read token for the fixed GitHub API endpoints, refuses redirects, and fetches public Git refs anonymously into a temporary bare repository. The stable tag must match both API and Git. The initial API-only comparison failed with an unspecified remote-read error; the replacement avoids cross-fork REST comparisons and emits sanitized failure categories. If API limits or unexpected data prevent verification it fails closed. Output includes a no-change or defer proposal and review checklist. It never applies an update, merges, pushes, tags, releases or deploys. The CI runs on relevant PRs and after pushes to custom.

**Scheduling limitation:** repository default branch is main, intentionally an unchanged upstream mirror. GitHub schedules and workflow_dispatch registration require the workflow on the default branch. The workflow_dispatch declaration is preparatory, not proof that manual dispatch is currently available. Do not modify main or change the default branch without an approved governance decision. Use the reviewed manual command meanwhile. A separately authorized external read-only schedule or a reviewed default-branch change can enable periodic checks; neither is configured by this PR.

For a new stable release, record exact SHA and release notes, review license/dependency/security/migration changes, prepare a temporary integration branch from custom and merge the verified stable commit with history preserved, then open a PR and run full regression/staging and rollback tests. Update the recorded baseline only after approval. Fork main may fast-forward to upstream/main separately after review, never with custom changes. Do not push core-* tags or publish to upstream registries. If the main branch is unchanged there is no real new upstream integration to rehearse; any synthetic trial must be identified as synthetic.
